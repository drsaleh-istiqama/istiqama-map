# اختبار الحمل (k6) — معيار القبول 2

> المعيار (أمر التنفيذ §14-2): بعد زرع 100 ألف مشروع و500 ألف شخص (ومليون صف صور)، ومع 300 مستخدم
> متزامن في k6: ‏p95 لـ `sync_pull` أقل من 800 ملي ثانية، وp95 لبلاطة MVT أقل من 300، وp95 للبحث أقل من 500.

## التشغيل

```bash
# 1) قاعدة خاصة جديدة + الحدود الإدارية + البيانات (≈ 25–30 دقيقة) + tokens.json
npm run load:seed -- --build                 # القاعدة الافتراضية imap_load
# 2) الاختبار: يشغّل PostgREST وبوابة خاصين (54343 / 54341) ثم k6 ثم يوقفهما
npm run load:test                            # 300 مستخدم: صعود 3 د، ثبات 10 د، نزول 1 د
# 3) حذف القاعدة بعد الانتهاء (5.4 GB)
.local/pg/bin/psql.exe -h 127.0.0.1 -p 54322 -U postgres -X -d postgres -c "drop database imap_load"
```

لا يمس الاختبار المكدّس المشترك (54321–54323، قاعدة `istiqama`) ولا يكتب إلا في قاعدة `imap_<label>`.

خيارات `load:seed`: ‏`--db`، `--projects` (100000)، `--collectors` لكل فرع (40)، `--parallel`،
`--tokens-only` (إعادة توقيع الرموز فقط)، `--vus` (300)، `--ttl-hours` (72). التوليد قابل للاستئناف:
إعادة الأمر تكمل من أول دفعة غير مسجّلة في `loadgen.progress`.

خيارات `load:test`: ‏`--vus`، `--ramp`، `--steady`، `--ramp-down`، `--think` (معامل زمن التفكير؛
0.5 = ضعف الحمل)، `--pool` (حجم مجمّع PostgREST، 20)، `--no-refresh-timer`، `--keep-stack`، `--label`.

## سيناريو k6 (`mix.js`)

كل مستخدم افتراضي حساب مستقل (`tokens.json`: رموز HS256 موقّعة بسر المشروع، و`aal2` للمديرين والإدارة
العليا)، فحدود المعدل في الخادم تبقى مفعّلة كما في الإنتاج.

| الفئة (من 300)                           | السلوك                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 24 مُدخلًا — «جهاز جديد»                 | مزامنة أولى كاملة لنطاق الفرع بصفحات 500 صف مع 0.5–1.5 ث بين الصفحات (زمن الكتابة في IndexedDB على هاتف ضعيف)، ثم يبدأ جهازًا جديدًا                                                                                                                                                                                                                |
| 204 مُدخلين + 36 مشرفًا                  | دورة مزامنة: `sync_push` لدفعة يوم ميداني (1–3 مشاريع بأرضها ومرافقها وصورها وصيانتها وكادرها وراتب، وتعديل لمشروع سابق) باحتمال 35٪ (10٪ للمشرفين)، ثم سحب تزايدي حتى `done`؛ 2–4 تحريكات للخريطة (6 بلاطات، تكبير 7–14 حول نقاط فرعه)؛ بحث بالعربية واللاتينية والرمز والقرية والكادر والمتبرع مع محاكاة الكتابة بتأخير 250 ملي ثانية؛ وزمن تفكير |
| 14 مدير دولة + 2 إدارة عليا + 20 مشاهدًا | سحب تزايدي (المديرون يتلقون الجداول المقيّدة ويُسجَّل وصولهم)، 3–6 تحريكات بعرض شاشة مكتب (12 بلاطة، تكبير أدنى)، 1–3 عمليات بحث                                                                                                                                                                                                                    |

الطلبات بالمسارات نفسها التي يستخدمها التطبيق: `/rest/v1/rpc/*` للمزامنة والبحث، ودالة Edge
`/functions/v1/tiles/{z}/{x}/{y}?f=…&e=…` للبلاطات. يُحكم على الميزانيات في **مرحلة الثبات** فقط.

## آخر قياس (2026-10-04، جهاز التطوير)

300 مستخدم، صعود 3 د، ثبات 10 د، نزول 1 د؛ 100 ألف مشروع، 500 ألف شخص، مليون صف صور؛ مجمّع PostgREST = 20؛
حد المعدل مفعّل؛ مؤقت `refresh_reports()` مفعّل. 125 694 طلبًا (143/ث)، صفر أخطاء، صفر 429، صفر عملية مرفوضة من
26 491 عملية `sync_push`.

| مرحلة الثبات                       | الطلبات |   p50 |      p95 |   p99 | الميزانية |
| ---------------------------------- | ------: | ----: | -------: | ----: | --------- |
| `sync_pull` (أولى + تزايدية)       |  15 538 |  39.5 | **85.2** | 139.6 | < 800 ✅  |
| — صفحات المزامنة الأولى (≈ 500 صف) |  11 790 |  43.3 |     93.6 | 150.3 |           |
| — السحب التزايدي                   |   3 748 |  26.6 |     50.3 |  71.7 |           |
| بلاطة MVT (دالة `tiles`)           |  78 816 |  27.0 | **65.5** |  99.9 | < 300 ✅  |
| البحث                              |   5 254 |  31.6 | **83.9** | 132.4 | < 500 ✅  |
| `sync_push` (حتى 50 عملية)         |   1 006 | 119.8 |    225.1 | 282.5 | —         |

اختبار إجهاد (`--think 0.25`، أي نحو أربعة أضعاف الإيقاع، 391 طلبًا/ث): المعالج مشبع (93–99٪)، فتتجاوز
البلاطات ميزانيتها (p95 ‏954 ملي ثانية) بينما يبقى `sync_pull` (478) والبحث (470) دونها. الاتصالات النشطة بالقاعدة
6 في المتوسط، فالاختناق في المعالج المشترك (k6 والبوابة في عملية Node واحدة تمر بها كل بلاطة مرتين)، لا في
PostgreSQL.

(مخرجات k6 الخام)، `k6.log`. سجلات المكدّس الخاص في `.local/loadtest/`.

> المتصفح وWorkbox، فكل تحريك يطلب كل بلاطاته من الخادم.
